Index arithmetic

No pointers anywhere — the tree structure is the arithmetic. For the node at index i (0-based):

parent
⌊(i − 1) / 2⌋
left child
2i + 1
right child
2i + 2
is a leaf
2i + 1 ≥ n
first leaf
⌊n / 2⌋
height
⌊log₂ n⌋

Because the tree is complete there are never gaps, so the array is always exactly n long and the height is guaranteed ⌊log₂n⌋ — no rebalancing needed, ever.

Two invariants, and what they do not say

Shape: complete — every level full except the last, which fills left to right.
Order: every node is ≤ (min-heap) or ≥ (max-heap) both of its children.

Heap order is much weaker than a BST's. It says nothing about siblings, and an in-order traversal of a heap is meaningless. That weakness is the point: it is cheap enough to maintain that insert and remove are both O(log n) with tiny constants.

On random input they come out close — repeated insertion is O(n) on average, because most elements stop climbing after a level or two. Press worst-case order to feed insertion the input that forces every element to the root, then run bottom-up heapify on the same 15 values: that is where the Θ(n) versus Θ(n log n) gap actually shows up.
